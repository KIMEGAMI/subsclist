# SubscList 月額480円リリース向け詳細テスト仕様書

## 1. 目的

SubscListを月額480円のPremiumサービスとして正式公開する前に、機能、課金、認証、通知、個人情報保護、障害時の復旧性、表示品質を検証する。

本仕様書は「画面が表示できる」だけでは合格としない。ユーザーが登録し、メール認証を完了し、480円のPremium契約を開始し、契約情報を安全に管理し、解約できるところまでを一連の業務フローとして検証する。

## 2. リリース前提

### 2.1 料金・プラン

| 項目 | 期待値 |
|---|---|
| Premium料金 | 月額480円（税込表示方針は事業者設定に合わせて統一） |
| 課金方式 | Stripeの月額Recurring Price |
| 無料トライアル | 実装されている場合のみ、期間と適用条件を全画面で一致させる |
| Free契約数上限 | 10件 |
| Freeカテゴリ上限 | 5件 |
| Premium契約数 | 制限なし、または仕様で定義した上限 |
| 解約 | Stripe Customer Portalまたは実装済みの正式な解約導線 |
| カード番号 | SubscListのDBへ保存しない |

### 2.2 環境

- 本番相当のHTTPS環境
- 本番MySQLとは分離されたテストMySQL
- Stripe Test ModeとLive Modeを混同しないこと
- Resendまたは採用SMTPの検証済み送信元
- 実ブラウザ: Firefox、ChromeまたはEdge、モバイル幅
- Node.js、Next.js、Prismaの実運用バージョン

### 2.3 テストデータ

| データ | 用途 |
|---|---|
| Free一般ユーザー | 制限確認 |
| Premium一般ユーザー | 有料機能確認 |
| 未認証ユーザー | 認証前アクセス確認 |
| 管理者ユーザー | 管理画面・メンテナンス確認 |
| デモユーザー | 一般ユーザー画面だけを表示するデモ確認 |
| ユーザーA/B | 他人の情報が見えないことの確認 |
| 期限切れトークン | 認証・パスワードリセット確認 |
| 10件、11件の契約 | Free上限境界値確認 |
| 月末・うるう年・31日開始契約 | 請求日計算確認 |

テストデータに本番ユーザー、実カード番号、本番APIキー、本番メールパスワードを使用しない。

## 3. 合否基準

### 3.1 必須リリースゲート

以下の1つでも失敗した場合、正式リリースを中止する。

- ユーザー登録からメール認証まで完了する
- パスワードリセットメールが届く
- Stripe Checkoutで月額480円のPriceが選択される
- 決済後にWebhookでPremiumへ反映される
- 解約後、契約期間終了時にFreeへ戻る
- Freeユーザーが11件目を登録できない
- ユーザーAがユーザーBの契約、支払い、ニュース、個人情報を取得できない
- 管理者以外が管理画面、管理API、メンテナンス解除を実行できない
- 本番DBに対してテストリセットや開発用マイグレーションを実行しない
- 外部メール送信の実送信テストが成功する
- 本番ビルド、Lint、主要テストが成功する

### 3.2 許容できない問題

- 課金金額の表示・Stripe Price・領収情報の不一致
- メール認証なしでログインできる
- デモリンクから管理者画面へ入れる
- ログアウトできない、またはログアウト後も認証済み画面が表示される
- CSRF、XSS、SQLインジェクション、IDORが成立する
- 料金、規約、特商法表記、プライバシーポリシーに古い価格が残る
- 定期ジョブの失敗が管理者に判別できない
- 決済失敗時にPremium権限だけが付与される
- アカウント削除後に個人データが残る

## 4. テストレベル

1. 静的確認: TypeScript、Lint、依存関係、環境変数、ルート一覧
2. 単体テスト: 日付計算、プラン制限、入力検証、ニュース・通知判定
3. APIテスト: 認証、権限、所有者分離、決済、CSV、管理API
4. DBテスト: マイグレーション、制約、Cascade削除、テストDB分離
5. ブラウザE2E: 登録から契約・解約までの主要導線
6. 外部サービス結合テスト: Stripe、SMTP/Resend、Google OAuthを使用する場合
7. セキュリティテスト: 認証回避、権限昇格、入力攻撃、レート制限
8. 運用テスト: cron、PM2、ログ、バックアップ、復旧、メンテナンス

## 6. セキュリティ詳細テスト

### 6.1 入力攻撃

- `<script>alert(1)</script>`を名前、メモ、カテゴリ、お知らせ、問い合わせ、CSVへ入力
- `" OR 1=1 --`、`' UNION SELECT`を検索・ID・CSVへ入力
- 長さ0、最大長、最大長+1、制御文字、改行、NULL相当値を送信
- URLに`javascript:`, `data:`, `file:`、認証情報付きURLを入力
- HTML属性、Markdown、URLクエリによる反射型XSSを確認

合格条件は、DBに保存されても表示時に実行されず、SQLエラーや内部情報が返らないこと。

### 6.2 認証・認可

- Cookieの改変、署名不正、期限切れ、空値
- `userId`、`subscriptionId`、`newsItemId`、`announcementId`の差し替え
- 一般ユーザーから管理API、cron API、Stripe webhookを呼び出す
- FreeユーザーからPremium APIを直接呼び出す
- ログイン前に保護ページ、API、静的データへアクセスする

### 6.3 CSRF・レート制限

- Origin/Referer不一致の状態変更リクエスト
- CSRFトークンなし、期限切れ、別セッションのトークン
- ログイン、登録、認証再送、問い合わせ、ニュースフィードバックを連打
- Webhook、cron、管理操作を大量送信

### 6.4 秘密情報

- Git、ビルド成果物、ブラウザレスポンスに`.env`内容が含まれない
- `STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET`、SMTPパスワード、AIキーがログに出ない
- cronのAuthorization値をコマンド履歴や画面へ直接露出しない
- 本番シークレットをテスト用`.env`へコピーしない

## 7. 外部サービス結合テスト

### 7.1 Stripe

1. Test Modeの480円月額Priceを作成
2. `active=true`、`type=recurring`、`interval=month`、`currency=JPY`、`unit_amount=480`を確認
3. Checkoutを作成
4. テストカードで決済
5. `checkout.session.completed`を受信
6. Premium反映を確認
7. Customer Portalから解約
8. `customer.subscription.updated/deleted`を受信
9. 契約終了後にFreeへ戻ることを確認
10. Live Modeでは同じテストカードを使用しない

### 7.2 メール

- 認証メールを実受信
- パスワードリセットメールを実受信
- 問い合わせ通知を管理者宛に実受信
- 更新通知を実受信
- 送信元ドメインがResendまたは採用SMTPで検証済み
- 送信失敗時に画面へ適切な日本語エラーを表示
- リトライしても同じメールが過剰送信されない

### 7.3 Googleログイン

Googleログインを有効化する場合のみ実施する。

- Redirect URIが本番HTTPSと一致
- state検証がある
- 未認証メールアドレスの扱いが仕様通り
